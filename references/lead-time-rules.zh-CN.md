# 倒推规则

## 定义

- **锚点 (D)**：大促 / 活动日期，所有时间都从它往回算。
- **窗口型候选**（体育盛会）：候选是一个时间段，不是一天。D = 大促窗口开始（活动必须上线第一天）。预热在窗口开始之前。窗口内的高峰（决赛 / 关键比赛日）是大促高峰，不是单独的锚点。
- **企划提前量**：制作开始前，决定活动所需的时间（优惠、角度、渠道）。
- **制作时长**：制作物料所需的时间。
- **制作提前量**：制作必须在 D 之前多久完成。必须 ≥ 预热期（物料要在预热开始时就准备好）。如果使用者给的制作提前量短于预热期，要标出来：预热开始时物料还没准备好。
- **预热**：D 之前的大促预热窗口。
- **持续天数**：大促本身持续多久。
- **缓冲**：加到每个截止日的宽松时间。使用者可改；默认 2–3 天。

## 公式（每个锚点 D）

- 大促窗口 = [D − 预热， D + 持续天数]
- 制作截止 = D − 制作提前量
- 制作开始 = 制作截止 − 制作时长
- 企划截止 = 制作开始 − 企划提前量

## 提前量来源

使用者提供的数字永远优先。**上次实际值优先于预估范围：**如果使用者提供了带实际提前量的上次活动（Stage 1 intake），就用实际值作为提前量，并在假设日志里标为“来自上次实际值”。如果使用者没有提供，就用以下预估范围，并把每一项都在假设日志里标为预估：

| 项目 | 预估范围 |
|---|---|
| 企划提前量 | 1–2 周 |
| 制作时长 | 2–4 周 |
| 预热 | 1–2 周 |
| 缓冲 | 2–3 天 |

预估范围是起步范围，不是标准。永远不要给单点预估（“制作需要 3 周”）。报告必须说明：信息缺失只允许给出宽范围预估。

## 迟到检查

把每个算出的截止日和今天（使用者当地日期）对比。任何已经过去的截止日 → 在时间线里标 LATE，并给出三个选项：压缩提前量（写出压缩后的数字 + 风险）/ 挪活动（换更晚的锚点）/ 放弃。永远不要在没有 LATE 标记的情况下输出已经过期的时间线。

## 冲突检查

两个活动的时间线重叠 → 标 CONFLICT + 按优先级给一个取舍建议：砍（去掉优先级更低的活动）、并（合并大促）或移（挪优先级更低的锚点）。由使用者决定；skill 只给建议。

**默认优先级**（使用者没给优先级时）：目标匹配度 + 客群匹配度（来自 Stage 1“为什么适合”的强度）。一个服务既定目标且命中目标客户的活动，优先于两者都不占的活动。

## 过载检查（按产能）

同一周内到期的制作套数超出使用者的产能 → 标 OVERLOAD + 建议：拉开工作、复用物料或砍范围。产能 = intake 里的团队人数（1 个人 vs 团队）÷ 制作负荷。审批链超过 1 环 → 加缓冲或标风险（审批即使不占制作时间，也占日历时间）。不要默认使用者能消化。

## 重跑规则

如果使用者在关口 2 之后改了选择 / 详情，重跑计算 + 冲突 / 过载 / 迟到检查，并重新确认时间线（重新过关口 2）。

## 关键路径

标出每个活动绝不能拖延的节点——通常是制作开始。如果这个节点拖延，大促日期就会拖延（或者砍范围）。要明确说出来。
