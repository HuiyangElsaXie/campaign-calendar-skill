# 倒推规则

## 定义与日期口径

- **S / E**：大促开始和结束日期，首尾均包含。单日活动 S = E；窗口型候选的锚点 D = S，窗口内高峰不另设锚点。
- **预热 W**：S 之前的天数。预热是独立阶段 [S - W, S - 1]；W = 0 时为空。**大促窗口**仅指 [S, E]。
- **持续天数 N**：含首尾的大促天数；E = S + N - 1。使用者给了起止日就采用，不编造“锚点前后若干天”的默认值。
- **企划提前量 L**：制作前决定活动所需时间。原“企划截止”列指**企划必须最晚启动**的日期；企划在制作开始前完成。
- **制作时长 P**：制作物料所需时间。
- **交付缓冲 B**：制作完成与预热开始之间的余量，**只计一次**，不从每个节点重复减去。
- **制作提前量 Q**（选填）：制作完成到 S 的天数。默认 Q = W + B。明确给出的 Q 必须至少为 W + B，否则标物料就绪冲突，请使用者调整 Q、W、B 或范围，不悄悄改数。

记录判断“今天”所用的市场时区 / 当地日期。默认按**自然日**计算并注明；工作日输入需有使用者的工作周和适用停工日。跨年保留完整年份；校验开始不晚于结束、时长非负。

## 公式与范围输入

    预热开始 = S - W
    制作完成 = S - Q       （默认 Q = W + B）
    制作开始 = 制作完成 - P
    企划最晚启动 = 制作开始 - L

本模型只设一次交付缓冲。审批或供应商另占时间时，单列依赖项及其时长，不再重复计入 B。使用者给的精确值可以算出精确日期，不属于预估；预估范围应输出日期范围（最早 / 最晚端点），不偷偷取中值。S、P 或关键依赖未知时，日期为条件性 / TBC，不是已确认排期。

候选大促窗口须与使用者的业务跨度相交。准备工作可早于跨度，并在时间线、日历与提醒中保留。大促窗口超出跨度时标出延伸部分，由使用者决定保留或缩短，不静默扩大范围。跨年跨度逐年生成日期。

## 提前量来源

本次明确输入优先。历史实际值仅在团队、渠道和范围可比时直接复用；条件变了先标明依据变化。明确更正优先于旧 brief，只澄清冲突点。

| 缺失项目 | 预估范围 |
|---|---|
| 企划提前量 L | 1–2 周 |
| 制作时长 P | 2–4 周 |
| 预热 W | 1–2 周 |
| 交付缓冲 B | 2–3 天 |

这是起步范围，不是标准或承诺。逐项记录预估、自然日口径与推导的 Q。本 skill 不提供默认大促持续天数。

## 迟到检查

按记录时区的 as_of 判断。授权历史模拟不机械标 LATE，也不证明实际完成；未来/进行中活动若准备节点过期，须提出缩减/延期/取消，列新日期、工时与风险并保留原日期。日期范围跨过 as_of 时标可能无法就绪。过去活动仅用于明确请求的复盘或授权模拟，不作为新的可执行建议；压缩不等于已经可行。

## 冲突与产能检查

窗口重叠触发**共用资源检查**，不直接判不可并行。人员、审批、库存或渠道承诺实际竞争时标 **CONFLICT**；依据缺失则标冲突待评估。按优先级给砍 / 并 / 移选项，由使用者决定。默认优先级：既定目标匹配度 + 客群匹配度。

判断 **OVERLOAD** 时，用同单位、同周期比较：每周各角色所需工时 vs 可用工时，或使用者确认可比的每周套数 vs 所需套数。合计并行承诺，纳入适配 / 审阅及使用者已告知的日常工作。团队人数不是吞吐量；不以人数除物料件数，也不因活动未重叠就宣称“无过载”。

只有需要判断可行性时才问粗略的瓶颈可用产能。产能或工作量缺失则标**产能待确认**，提出保守范围，不编小时数。审批、供应商 / 印刷 / 运输约束在适用时单列负责人、截止日、状态；关键依赖未确认时，计划仍有条件。

## 重跑与关键路径

关口 2 后若选择、日期、范围、成本约束或产能改变，重跑日期、迟到、预算、冲突和过载检查，重新确认关口 2。标出限制每个活动的依赖 / 节点（常为制作开始），说明它错过时什么会延期或必须砍掉。关口 2 不能把未知事实变成已核实事实。


## v1.1.0 模式与策划节点补充

以上 start-by 是策划开始，不是策划完成；模型分别保存 planning_start、planning_deadline。经用户授权的历史模拟仅表示情景，不机械标 LATE，也不表示已完成。未来/进行中的活动若准备节点已过期，必须给缩减、延期、取消选项，实际准备未证实就仍有条件。详见 [结构化计划](structured-plans.zh-CN.md)。
