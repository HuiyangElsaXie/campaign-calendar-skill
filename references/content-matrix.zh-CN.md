# 由覆盖需求决定内容矩阵

先复用用户已给业务、受众、渠道、决定及纠正，再补必要信息。范围以选中活动 ID 为准。独立核心主题与平台改写分开：平台变多不等于重复研究。本 skill 产出选题、简报和任务，真实文案、设计文件、发布分别算交付。

先列每活动的受众问题和证据缺口。核心逐项记录内容支柱、受众、问题、子选题、资产类型、目的、漏斗阶段、CTA/去向、主渠道、复用方法、发布顺序、交付/发布日期、角色和声明证据要求，并关联 coverage/source ID。平台改写引用一个核心，说明形式、长度、CTA 的适配；需要新研究的问题另立核心。

数量来自必要问题覆盖、已有资产、边际价值和角色工时。低资源版可合并相关问题；标准版只有在价值和容量允许时拆开。两者都不是每活动每平台固定发几条。说明可选项及削减理由；每种情景的必需 coverage ID 均须覆盖，不为凑数重复相同观点。

每项内容落到任务：核心一次研究、写作、必要改写、审核、交付和协调。记录负责人或待分配、工时区间/单位/依据、日期、依赖、验收及上游 output ID。共用工作算一次，翻译/改写/审核仍计时；跨活动按同周同角色比较，不能人数除以资产数。超载须给削减/合并/移动方案，不发明 FTE。

教育等资格敏感业务须在简报中列真实年龄、年级、考试阶段的证据要求；缺失声明从公开文案暂扣。不得虚构课程、师资、考点授权、成绩、价格或 CTA 路由。可选写作 skill 不可用时，本地矩阵仍可直接使用，见[交接规范](downstream-handoffs.zh-CN.md)。
