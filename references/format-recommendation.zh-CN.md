# 形式推荐——目标优先 + 约束过滤

skill 如何为每个活动推荐最多 3 种可行形式。推荐来自一串漏斗问题（见 `templates/intake.md` Stage 2），不是按行业查表——“零售”太宽泛，定不了形式（母婴零售 ≠ 露营零售 ≠ 茶零售）。

## 第一步——目标 → 候选形式（目标是首要键）

| 目标（漏斗 F1） | 候选形式 |
|---|---|
| 清库存 / 季末 | 清仓、买一送一、组合装 / 礼盒（走量） |
| 拉新 | 抽奖、联名 / 合作、快闪 / 试吃（试用带动拉新） |
| 提高客单价 | 满赠、组合装 / 礼盒 |
| 新品发布 | 发布活动、预售、试吃 / 试用 |
| 复购 / 留存 | 集点 / 会员卡、组合装 / 礼盒（囤货装） |
| 送礼场合 | 组合装 / 礼盒、满赠 |
| 引流 / 曝光 | 快闪 / 店内活动、抽奖、联名 / 合作 |

## 第二步——约束过滤（排除）

把每个过滤器应用到第一步的候选形式上。硬约束排除不安全 / 不可行选项；偏好只对剩余候选排序，不把已排除形式重新塞回来。

| 漏斗答案 | 过滤器 |
|---|---|
| 渠道 = 仅线上（F5） | 排除快闪 / 店内活动、店内试吃 |
| 预算 = 已知紧上限（F6） | 使用者已给成本超出同范围上限时排除；成本未知则有条件。在剩余选项中优先较小范围，不承诺必然便宜 |
| 毛利 = 薄（F3） | 排除深度折扣。不默认满赠 / 买一送一符合毛利；核对使用者单品经济与价格底线，未知则毛利可行性待确认 |
| 价格 = 高单价（F2） | 优先预售、发布活动、联名（建立信任）。避免闪电折扣 |
| 购买频次 = 一次性（F4） | 排除集点 / 会员卡（没有复购可奖励） |
| 购买频次 = 重复购买（F4） | 集点 / 会员卡和囤货组合装保留 |
| 产品不可试（从 Stage 1 产品品类推断，例如服务、无形产品） | 试吃不适用——在形式列表允许的情况下换成免费试用 / 免费咨询 |

## 第三步——输出

- 推荐**最多 3 种可行形式**，每种附一句话理由，理由必须引用使用者的具体答案（目标 + 价格 + 毛利 + 频次 + 渠道 + 预算）。
- 永远不要写通用理由（“这个很流行”、“最佳实践”）。如果理由引用不了使用者答案，这个形式就不推荐。
- 只有 1 种可行形式也可以；没有可行项时说明约束，建议改范围 / 时间，不为凑数量硬推。
- 折扣 / 满赠 / 买一送一在已知时，用使用者售价、商品 / 赠品成本及价格底线核对毛利。同品买一送一，卖一件的收入须先覆盖两件成本，尚未计其它费用；成本未知则有条件，不能凭形式名说“成本可控”。
- 使用者选、混搭或提供想法，但保留成本、日期和可行性约束及未决风险；选择不等于这些约束已通过。
- 推荐的形式可能增加物料（例如试吃 → 样品；快闪 → 易拉宝）。物料清单会自动接上。

## 规则

- 任何漏斗问题都可以跳过 → skill 不用该项过滤，并在报告里把缺失的输入标为假设。
- “不确定”= 该问题无约束（等同于跳过）。
- “其他（自己输入）”的答案按原样使用——skill 按它们推理，永远不强行塞进固定选项。
- 预设（`references/activity-format-presets.md`）是菜单；本文件是挑菜单的逻辑。预设是起点，不是经验证有效的赢家。
- 永远不要把推荐的形式说成效果承诺。
