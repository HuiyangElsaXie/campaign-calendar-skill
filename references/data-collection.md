# Data Collection & Retention Checklist

Purpose: collect DURING the campaign, so the post-campaign report / review has
something to report. No data collected during = no review after.

## Owner

One daily data collector per campaign (intake item). They fill the daily log every
day of the campaign — not after. Platforms reset, dashboards change, memory fades.

## What to collect

| Category | Metrics | Source |
|---|---|---|
| Sales & conversion | Daily sales (total + per product), orders, discount-code redemptions per code (→ per channel), QR scans per code, UTM sessions + conversions per channel | POS / website analytics / code + QR dashboards |
| Traffic | Website sessions, landing-page views, per-channel clicks (UTM), social reach / impressions / engagement per post, email open + click rates, SMS delivery + click | Analytics / platform insights / ESP |
| In-store | Foot traffic (if counter), daily in-store sales, in-store coupon redemptions, stamp cards issued / completed | POS / counter / manual count |
| Ground / 地推 | Flyers distributed, sign-ups / leads collected, gifts given, samples given, photos taken at photo wall, qualitative notes | Manual count + sign-up sheets |
| Customers | New vs returning customers (if trackable), new followers, new email / SMS subscribers, reviews posted during the campaign | POS / platforms / review sites |
| Costs | Actual spend per item (keep receipts / invoices), actual quantities used vs planned (wastage), staff hours | Receipts / invoices / timesheets |
| Qualitative | Customer comments / complaints, staff observations, competitor moves during the campaign, photos of displays (before / during / after), screenshots of social posts + key comments | Notes / photos / screenshots |

## Retention rules

- Keep RAW exports (CSV / dashboard exports), not screenshots of dashboards alone.
  Screenshots are evidence; raw data is what the review calculates from.
- One folder per campaign. File naming: `YYYY-MM-DD_<metric>_<source>`.
- Collect DAILY during the campaign. Do not wait until after.
- Do not delete raw data before the review is done. After the review, archive
  (do not delete) — the next campaign may need the baseline.
- If a metric was not collected, mark it "not collected" in the log. Do not
  reconstruct it from memory after the fact.

## Privacy & consent (Canada)

- Sign-up forms (email / SMS) must include a consent checkbox — commercial
  electronic messages require consent under CASL.
- Customer photos (photo wall, event shots) need the person's consent before
  use in any post-campaign material.
- Collect only what the review needs. No extra personal data.

## What the data feeds — post-campaign follow-up

The follow-up list (what to organize + report after the campaign) is in
`references/post-campaign-followup.md` — list only, no operations.

The review itself (analysis, conclusions, recommendations) is a separate
(future) skill. This skill prepares the data + the follow-up list so the
review skill has everything it needs. It does not do the review.
