# 研究协议——AI 如何补日期缺口

skill 不存所有答案。它存的是：要研究什么、怎么研究、查到的东西有几分可信。研究发生在 Stage 1、推荐报告之前。研究只补日期缺口——永远不碰使用者的业务事实（卖什么、卖给谁、什么时候买 / 用）。

## 收录标准

一个日期进不进通用层，看这个国家的商铺 / 品牌会不会为它做活动——不只看它是不是法定节假日。被采用的 / 商业性的日期（例如中国的情人节和圣诞节、6 个现成国家都有的万圣节）属于通用层，标 commercial（不是法定节假日）。

## 什么时候研究（触发点）

- 小众国家（没有现成通用层）→ 研究并建它的通用层。
- 客群文化日期不在任何现成层里 → 研究这些日期。
- 公告型日期（Prime Day、零售商自定大促）→ 查官方公告。
- AI 从常识里提出的任何日期 → 在作为已确认呈现之前先验证。

## 信源分级

1. 政府发布的假日列表（法定节假日的权威信源）。
2. 官方公告（零售商 / 品牌官方页面；体育盛会的联合会 / 组委会公告）。
3. 可靠参考源（例如维基百科、主流新闻）——农历 / 可变日期需要两个一致的独立信源。
4. 市政府活动日历、BIA 列表、社区协会公告（本地社区活动）。
- 永远不用：内容农场、AI 生成的清单文、社媒帖、无日期页面、上一年日期当今年用。

## 流程

1. 用带年份的查询搜索（例如“Canada statutory holidays 2027”，不要搜泛泛的）。
2. 打开信源页面自己看——永远不只信搜索摘要。
3. 农历 / 可变日期：两个独立信源必须一致。
4. 信源冲突 → 标冲突、两边都呈现、问使用者。
5. 没找到可靠的 → 标 UNVERIFIED，问使用者。
6. 每个研究过的日期都要记信源 + 可信度标签。

## 可信度标签（显示在 Stage 1 报告里）

- **base-verified**——来自现成通用层。
- **government-sourced**——研究过，政府信源。
- **official-announcement**——研究过，官方公告。
- **unverified**——没能验证。使用者必须先确认，它才能成为锚点。

## 红线

- 使用者提供的日期是权威的——永远不要“验证”使用者自己的日期。
- 业务事实（产品、客群、季节）是使用者的——研究只补日期缺口；不“核查”使用者的业务。
- 研究过的日期没有信源就永远不作为已确认呈现。
- 研究建的小众国家层在使用前先给使用者确认，并标注“research-built, please confirm”。

## 工具无关

用 agent 可用的网络搜索工具。本协议不假设具体工具、浏览器或运行环境。如果 agent 没有网络访问，跳过研究，把缺口标 UNVERIFIED，并请使用者提供日期。
