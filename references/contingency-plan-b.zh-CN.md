# 应急 Plan B——突发情况与预先定好的应对

原则：Plan B 只有在活动开始前定好才有用。在关口 2（时间线确认）时，使用者预先定好“提前定好”列里的事项，并指定一名 Plan B 决策人（intake 项）——活动进行中唯一能不经开会就批准执行 Plan B 的人。

本 skill 不实时监控活动。使用者 / 决策人注意信号并执行 Plan B。

## 在关口 2 预先定好（清单）

- 雨天日期 / 室内备用方案（户外活动）
- 价格底线——允许的最低价格 / 最深折扣，慌乱时也绝不突破
- 折扣码上限（最多兑换次数）+ 停用开关（谁能禁用一个码）
- 动态 QR / 短链接（目的地可改，不用重印）
- 替补排班（有人生病时谁顶上）
- 投诉统一口径（提前批准的一段话）
- Plan B 决策人（一名）

## 情况

| 情况 | 信号 | Plan B | 提前定好 |
|---|---|---|---|
| 恶劣天气（户外 / 地推） | 预报变坏 / 当天下雨 | 移到室内、改成仅线上，或用雨天日期 | 雨天日期 + 室内备用方案 |
| 到店 / 流量远低于预期 | 到活动中期，人流 / 点击远低于计划 | 社媒 + 邮件群发、员工街头推广、推文投放（如果有预算）、延长大促 | 谁能批准投放 / 延期 |
| 断货：大促产品售罄 | 库存归零 | 换替代产品、雨票 / 预售、延长大促到补货日期、一次性同步所有渠道（网站 + 社媒 + 店内招牌） | 替代产品 + 补货日期来源 |
| 网站 / QR / 链接挂了 | QR 扫描归零 / 收到报错 | 换备用链接（动态 QR）、发通知、大促延长挂机时长 | 动态 QR + 备用链接 |
| 印刷延误 / 物料没准备好 | 印刷商错过交付日期 | 数字优先应急（社媒 + 邮件 + 手写店内招牌）、推迟上线、只印必需品 | 哪些物料是必需、哪些是锦上添花 |
| 人手不足 | 员工请假 / 没来 | 替补排班、简化店内布置、缩短营业时间 | 替补排班 |
| 社媒帖被删 / 账号受限 | 帖子消失 / 收到账号通知 | 备用账号、退回邮件 + 网站、申诉 | 备用账号存在 |
| 负面评价发酵 | 投诉帖获得热度 | 几小时内公开回应、转到私下处理（私信 / 电话）、不要删评论、用统一口径 | 统一口径 + 谁回应 |
| 竞品同日促销 | 竞品公告 | 稳住——用价值差异化，不要降价。永远不要在慌乱中跌破价格底线 | 价格底线 |
| 折扣码泄露 / 滥用 | 兑换数超出目标人群激增 | 设兑换上限、改单次码、禁用泄露的码、已兑换的照常兑现 | 折扣码上限 + 停用开关 |
| POS / 结账挂了 | 交易失败 | 店内现金应急、线上手动订单表、延长大促 | 备用现金 + 手动表单已准备好 |
| KOL / 网红放鸽子或迟到 | 错过发布时间 | 发布备用的自有内容、改期、用预先准备好的内容 | 内容提前准备好 |
| 礼品 / 样品发完 | 赠品库存归零 | 换替代品、雨票、每人限领 1 份（提前定好） | 每人限领数 |
| 场地 / 许可证问题 | 场地取消 / 许可证被拒 | 备用场地、改仅线上、改期 | 备用场地 |
| 展位申请被拒 / 没拿到展位 | 主办方拒绝申请 | 退回无实体展位的品牌联动：线上大促 + 本地发传单 / 合作店铺快闪；或申请另一个本地活动 | 备用本地活动 / 线上回退方案已提前定好 |
| 体育盛会延期 / 取消 | 主办方公告 | 把活动和赛事解耦：改通用角度（例如“足球季”→“夏日观赛夜”）；大促继续，去掉赛事特定说法 | 通用回退角度已提前定好 |
| 数据没收集 | 每日日志连续 2 天以上为空 | 收集人当天从原始导出补上；如果补不了，标“not collected”——永远不要凭记忆重建 | 每日收集人已指定 |

## 边界

- Plan B 是提示 + 预先决定，不是保证。skill 不能防止突发情况。
- 如果执行了 Plan B，在每日日志里记下来（发生了什么、做了什么、什么时候）——它会成为复盘里“哪些没按计划走”的一部分。
