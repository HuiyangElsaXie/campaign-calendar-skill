# 信息收集表 — 两阶段

在第一阶段选定之前，绝不问第二阶段的问题。缺失 → 暂定 + 明确标注假设。

**输出语言（在调用时问）：** 英文或中文。如果使用者已经说明了，就用它——绝不重复提问。输出为中文时读 `.zh-CN.md` 版本的文件。

## 第一阶段 — 轻量信息收集（用于推荐活动）

| # | 问题 | 答案 |
|---|---|---|
| 1 | 国家（6 个现成层：加拿大、中国、美国、英国、日本、韩国；其他 → 按研究协议现搜） | |
| 2 | 时间跨度 — 开始日期和结束日期（一个临时活动、一个季度、一个季节、一年 — 使用者自己定） | |
| 3 | 卖什么？（产品 / 服务品类 — 例如母婴用品、露营装备、茶叶） | |
| 4 | 卖给谁？（目标客户 + 文化背景 — 例如本地礼品买家；华裔加拿大家庭） | |
| 5 | 什么时候买 / 用？（使用季 / 购买周期、高峰、有没有季前？— 例如露营夏天是高峰，春天是季前） | |
| 6 | 品牌 / 自定日期：品牌年庆、自定大促日（可没有） | |
| 7 | 城市 / 都市区（选填 — 填了按本地给展位建议，没填按品牌模式） | |

**城市关口（问一次，在生成第一阶段报告之前）：** 如果使用者在调用时没有给 city，在生成报告之前多问一句：“是否需要定位具体 city？” 定位 city 才能解锁没有 city 就没法查的本地机会 —— 本地社区摆摊、本地展位、主办城市体育盛会。没给 city 就按品牌模式走（只有品牌曝光提示，没有具体的本地摆摊机会）。如果已经给了 city，不要再问。本地机会必须确定信源后才能提出（按研究协议）；绝不凭记忆或推测提本地活动。
| 8 | 上次活动（选填 — 去年 / 上季度：做了什么、效果如何、实际提前量；校准提前量 + 过滤候选） | |
| 9 | 已知竞品活动 / 日期（选填 — 避开正面撞期，或有意对打） | |

## 第二阶段 — 使用者选定活动之后

### 全局（一次）

| # | 问题 | 答案 |
|---|---|---|
| G1 | 渠道与产能：网站（有 / 无）、门店数、社媒账号数（按平台）、矩阵账号（有 / 无，哪些平台） | |
| G2 | 提前量：企划 / 制作 / 预热 — 使用者可跳过 → 宽范围预估 + 标注假设 | |
| G3 | 整个时间跨度总预算（选填 — 预算汇总既对单个活动、也对总数做对照） | |
| G4 | 团队人数 + 审批链（至少问人数 — 供按人力产能的过载检查使用；审批链 > 1 → 加缓冲 / 标风险） | |

### 逐个选定活动

先定大促日期范围，再走漏斗 (F1–F6)。漏斗从宽泛（目标）逐步缩小到具体（预算），这样 skill 能附理由推荐 2–3 个形式。
每道题都给固定选项 + “其他（自己输入）”。任何一题都可以跳过 → skill 不用该项做过滤，并把缺失输入作为假设标注出来。

形式推荐：skill 经 `references/format-recommendation.md` 运用漏斗答案（目标 → 候选 → 约束过滤 → 2–3 个形式附理由）。使用者选、混搭或用自己的想法覆盖 — 使用者自己的想法永远优先。

## 规则

- **预填（绝不重复提问）：** 在问任何问题之前，先检查使用者在调用 / 对话中已经提供的内容，直接用它。绝不重复问使用者已经回答过的问题。如果不确定某个回答是否覆盖了某个问题，简短确认一句（“你刚才说 X——这里就用它了”），而不是重新提问。
- 第一阶段先问：国家 + 跨度 + 卖什么 + 卖给谁 + 什么时候买 / 用 + 品牌日期。
  在选定之前不要问渠道、提前量、预算或形式。
- 品牌 / 自定日期是使用者输入的槽位。绝不推断。
- 第二阶段预算带成为最终报告对照的上限（逐个活动）；整个时间跨度总预算对照的是总和。
- 第二阶段人流估算 + 领取率供礼品 / 样品数量用（不知道 → TBC）。
- 第二阶段形式可能增加物料（例如试吃 → 样品；快闪 → 易拉宝）。
- 复用的资产从制作负荷里减掉 — 列出复用了什么。
