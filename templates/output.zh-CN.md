# 输出结构 — 两阶段

## v1.1.0 结构化约束（优先于旧数量默认）

使用 [结构化计划](../references/structured-plans.zh-CN.md) 和 [内容矩阵](../references/content-matrix.zh-CN.md)。复用已知输入；人数不换算 FTE。独立主题、平台改写分开，数量由必要问题覆盖和工时决定，下列旧数量仅供条件选项，不自动采用。七个完整年份日期分开，素材完成早于预热。预算/容量未知须保留；所有选中 ID、详情、节点、来源及结束标记均需 verify；候选合作不混入正式日历。

## 第一阶段 — 活动推荐报告（先出）

简单 + 互动。见 `templates/stage1-recommendation.md`。
该时间跨度的候选活动（日期、活动、为什么适合、可能类型），再加使用者下一步要定的事（选活动 + 填第二阶段详情）。
还没有倒推、物料、预算、时间线。

## 第二阶段 — 最终输出（按此顺序，在选定 + 填完详情之后）

### 1. 时间线（先出 — 主干）

按时间顺序的表格。每个活动一行。

| 活动 | 企划截止 | 制作开始 | 预热开始 | 大促日期 | 状态 |
|---|---|---|---|---|---|
| … | … | … | … | … | 草稿 / 已确认 |

规则：按日期排序。按 lead-time-rules.md 只计一次交付缓冲，注明日期 / 时区口径。有依据的资源冲突和过载在行内标出（冲突 (CONFLICT) / 过载 (OVERLOAD)），旁边附取舍建议。选定的活动撞上已知竞品大促日期时，在状态列标竞品 (COMPETITOR)，并写使用者立场（稳住 / 差异化 / 对打）。
展位活动多一个里程碑：展位申请截止日（保留信源日期，不为固定顺序移动它）。任一截止日已过今天，标迟到 (LATE) 并给三个选项（压缩提前量 / 挪活动 / 放弃）。

### 物料清单（逐个活动的附件，随时间线）

每个活动：是什么 + 多少 + 何时要 + 使用阶段（预热用 / 大促用 / 两者）。
数量规则见 `references/materials-checklist.md`。文案矩阵：标注需要 / 不需要 + 份数（内容归 06）。线下物料（易拉宝、传单、礼品、二维码）只有活动有线下存在时才出现。

### 数据收集清单（逐个活动的附件，随时间线）

活动中要收集 + 保存什么，这样活动后复盘才有数据。
见 `references/data-collection.md`：每日日志（负责人：每日数据收集人）、销售 / 流量 / 店内 / 地推 / 客户 / 成本 / 定性指标、保存规则（原始导出、一个活动一个文件夹、每天、复盘前不删）、隐私与同意（CASL、照片同意）。

### 应急 Plan B（逐个活动的附件，随时间线）

对常见 disruption 预先定好的应对。见 `references/contingency-plan-b.md`。
在关口 2 预先定好：雨天日期、价格底线、折扣码上限 + kill switch、动态二维码、替补排班、统一口径、决策人。skill 不实时监控；使用者 / 决策人执行 Plan B 并在每日日志里记录。

### 2. 日历视图（第二出）

同样数据画成日历：业务跨度及更早准备期内每个月一个块（短跨度按周），每块列出该时段的企划截止、制作开始、预热开始和大促日期。

### 日历标记（视觉报告 / PDF）

- 企划截止：对应活动色的空心粗边方框（整个日期格加粗边）。
- 制作开始：对应活动色的实心圆（数字旁圆点）。
- 大促日：对应活动色的实色填充。预热日：对应活动色的浅色。图例解释所有标记。

### 提醒清单（日历视图的一部分）

即将到来的截止日，按日期排序：企划截止、制作开始、预热开始。
默认窗口：30 天（使用者可调 — 使用者可设任意窗口）。
使用者把这份清单导入自己的日历工具。本 skill 不自动提醒。

### 3. 详细报告（第三出 — 给老板看的计划文档）

针对选定的时间跨度：

1. 一句话业务目标与主要成功信号；基线 / 测量来源未知则 TBC。
2. 活动总览（来自时间线，用散文写）。
3. **索引表** — 每个活动一行：活动 | 锚点日 | 预热开始 | 大促日期范围 | 一句话思路（一行概念）。
   索引表下区分已核实 / user-set 锚点、预估准备日期和未核实公共日期。
4. 里程碑（最重要的那些日期）。
5. 逐个活动详情（在索引下面：关键日期、物料、线下物料、预算行、数据收集、Plan B — 每个活动一块）。
6. **竞品撞期** — 每个撞上已知竞品大促日期的选定活动：竞品是谁、日期、使用者立场（稳住 / 差异化 / 对打）。没有已知撞期 → 写“本时间跨度内没有已知竞品撞期”。
7. 产能依据 / 状态：同周期所需与可用工时或可比吞吐量；并行工作、适配和瓶颈；缺依据则待确认。
8. **预算汇总** — 物料清单数量 × 单价。单价没给标 TBC；任一单价 TBC 则总数 TBC；只有使用者给了上限才做上限对照。既对照逐个活动的总数与各自预算带，也对照所有活动总和与整个时间跨度总预算（如给了）。
9. **假设与未知日志（强制）** — 每个 TBC 日期、每个预估提前量、每个默认值。没有日志 = 输出不完整。

活动后跟进（在活动之后，不属于上面这些交付物）：推荐的数据整理 + 报告事项列表 — 见
`references/post-campaign-followup.md`。只列项，不写操作。复盘本身是另外一个未来的 skill。

格式：Markdown 表格（可粘贴进 Sheets / Notion）。不承诺 .ics / 日历集成。
